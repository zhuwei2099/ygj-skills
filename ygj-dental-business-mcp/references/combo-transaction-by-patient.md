# 组合交易金额 · 按患者汇总统计规则 v1.0

**定稿：2026-10-15**｜需要把交易明细还原成「治疗组」再按患者汇总金额时读本文件。

**核心思路**：**先把交易行还原成「治疗组」，再按组算钱、按患者汇总**。

## 数据源与适用范围

- 交易明细：`clinics_list_bill_docs`（一行 = 一条收费明细）；组合价目表 `basedatas_list_charge_combs`；项目价目表 `basedatas_list_charge_items`；患者档案 `patients_get_details`（姓名、病历号、归属店）
- 统计范围：**全量行**（组合行按治疗组归并、未挂组合的单项目行逐行独立），**不限定 `labelLevel1`**
- 禁用：`refundAmount` / `chargeRefundAmount`（样本恒 0）；`status`（样本全 0）

## 核心概念

| 概念 | 定义 |
| --- | --- |
| 组合行 / 单项目行 | `combId` 非空 / 为空 |
| 主项目行 | `mainItemId` 有值 **且** `chargeItemId == mainItemId` |
| 治疗组 | 统计最小单元：组合行按组键归并成一组；单项目行**每行独立成组** |
| 互补副本 | 同 `(billId, billDetailId)` 出现两次、字段互补的两行 |

## 第 1 步：互补副本合并（先于组构造，必做）

- 判据键 **`(billId, billDetailId)`**：同键出现多次 → **按字段求和合并，不删行**
- 合并规则：`payAmount` / `refundCount` **相加**（Decimal）；`fdiToothCodes` / `doctorName` / `chargeItemShowName` / `chargeItemId` / `combName` / `unit` 取**首个非空**；`optDateTime` 取**较早**一个
  - ⚠️ **适用范围限定（2026-10-15.12）**：本节「合并」**只适用于互补阶段行**（金额与数量落在**互斥位置**的两批写入，见下一条）。同键若出现**反向冲销对**（收 `+x/+n` ＋ 退 `−x/−n`，两个位置都非零）→ **禁止合并**，须按两笔独立事件保留（合并会把退费抵消成 0）。判据与实现见 [revenue-and-deal-count.md](revenue-and-deal-count.md) §五 第 5 步。
  - ⚠️ **归期时间的两种取法**：治疗组聚合场景取**较早**（本节）；**分部 / 门店业绩的区间归期**场景取**较晚**（`max`，以最终交易事件为归期，避免跨零点把整行丢出区间）—— 见 §五。
- 为什么不能删行：两个写入批次互补（12:17:21 批 `payAmount=0/refundCount=有值`，12:17:39 批相反），删任一条都**丢金额或丢数量**；苏州样例 367 → **362**

## 第 2 步：治疗组构造（组键）

- 组合行组键 = **四元组 `(combId, mainItemId, patientId, billId)`**，四字段一律 `str()` 字符串化后比较
- 单项目行：**每行独立成组**，不与其他行合并
- 🚨 **铁律：组键禁用交易表 `id`** —— `id` 行级标识**不唯一**（苏州 232 行只有 54 个去重 `id`），用它当组键会把不同收费单的行错并（曾致补牙数量 161 → 157）；去重键固定 `(billId, billDetailId)`

## 第 3 步：逐组聚合（一行 = 一个治疗组）

| 指标 | 公式 | 说明 |
| --- | --- | --- |
| 数量 | 组合组 `Σ refundCount`（**仅主项目行**）；单项目组整行 | 组内无主项目行 ⇒ **数量 0**（金额照计） |
| 组合标价合计（快照） | `Σ(originPrice × refundCount)`，**组内全行** | 交易时点快照价，**唯一对外标价口径** |
| 实收金额 | `Σ payAmount` 组内全行 | 退款行 `payAmount<0` 自然冲减成净额 |
| 折扣额 | 组合标价合计 − 实收金额 | 差额即折扣 |
| 主项目金额 | `Σ payAmount` 仅主项目行 | **仅供参考**，非统计口径 |
| 退款金额 | `Σ payAmount`（组内 `payAmount<0` 行） | 用于异常披露 |
| 0 元行数 | 组内 `payAmount==0` 行数 | 赠送 / 免收，**保留**、不影响金额 |
| 组内行数 | 组的行数 | 核对用 |

- 金额与数量聚合范围**不同**（铁律）：数量只认主项目行；金额全行（主项目 + 材料 + 加收）
- **符号不一一对应**：`refundCount` 与 `payAmount` 符号不必然一致（例：`payAmount=-120` 而 `refundCount=0`）⇒ 金额与数量**各自独立聚合**，不互相推导

## 第 4 步：分类与命名（明细「分支」「二级分类」列）

- 三层优先级命中即止、不回退、缺失桶单列（与「交易表 labelLevel 层级统计规则」完全一致）；JOIN 键陷阱同（`combId → charge_combs.id`；`mainItemId/chargeItemId → charge_items.chargeItemId`）
- `labelLevel1` → 一级；`labelLevel2` 数组逐元素展开；标签门店级、逐店拉表

## 第 5 步：按患者汇总

- 汇总维度 = **`patientId`（一人一行）**；汇总表 **14 列**：患者姓名、病历号、归属店、治疗组数、其中组合组数、其中单项目组数、数量合计、组合标价合计(快照)、实收金额、折扣额、退款金额、0元行数、涉及组合数、涉及组合名（组合去重计数；组合名先排序再「；」连接）
- 明细表 **18 列**：患者姓名、病历号、收费日期、收费时间、项目名称、组合名称、行类型、二级分类、组内行数、数量、组合标价合计(快照)、实收金额、折扣额、主项目金额、牙位、医生、分支、备注
- 排序：汇总表按实收金额**降序**、同额按姓名升序；明细表按收费时间、患者姓名、实收降序
- **病历号是门店级、跨店重号** ⇒ 对外输出必须带门店名

## 勾稽校验（7 条，须全绿）

| # | 校验项 | 校验规则 |
| --- | --- | --- |
| ① | 实收守恒 | 逐组明细 Σ实收 == 按患者汇总 Σ实收 == 交易表 ΣpayAmount |
| ② | 标价守恒 | Σ快照标价 / Σ折扣（快照标价 − 实收） |
| ③ | 组数守恒 | 汇总表 Σ治疗组数 == 明细表行数（组合组数 + 单项目组数） |
| ④ | 退款核对 | 原始行 `payAmount<0` 的行数与金额逐一比对 |
| ⑤ | 0 元行核对 | 合并前 0 元行数 → 合并后 0 元行数（互补副本不重复计） |
| ⑥ | 合并不变性 | 合并前后 Σ实收 与 Σ快照标价 完全相等 |
| ⑦ | 覆盖面 | 患者数、组合组数与基线明细核对 |

## 边界与坑

- 组内无主项目行的组合组：数量 0、金额照计（苏州 4 组，如「根管治疗·单根管牙」只有材料 / 加收行）
- 退款行不与任何正向行共享 `billId`（苏州 7 行、2 位患者、3 个退款组）
- 0 元行原始 14 行（5 行互补副本）→ 合并后 9 行，保留
- 多步骤组合：单张收费单只含其中一个 step ⇒ 用价目表挂牌价会虚高（放弃「价目表对照」口径的原因）
- 同患者同日多单：组键含 `billId` ⇒ 天然拆组、不做并单
- 跨店：`patients_list_*` 含跨店记录，多店统计必须按 `clinicId` 过滤后再统计
- 符号不一一对应 ⇒ 金额与数量独立聚合（见第 3 步）
